### [23:58] Lint-debt location measured — my own hypothesis refuted   (branch: develop · commits: none — memory only)

**Synopsis:** I had suggested the 743→7,222 lint-error growth probably lived in
`archive/`, `ylsbrain/` and `.claude/hooks/`, which would have reduced the
cleanup ticket to a one-line `ignores` edit. Measured it. **Wrong.** The
shortcut does not exist; the debt is in real application code.

**What worked + Evidence:**
- `git ls-files "*.ts" "*.tsx" "*.js" "*.jsx" | awk -F/ '{print $1}' | sort |
  uniq -c` — instant, and decisive: `components` 484, `app` 171, `lib` 120,
  `archive` 49, `hooks` 41, `tests` 40, `types` 10, `.claude` 10 — ~937 total.
  **`ylsbrain/` does not appear at all: zero lintable files, it is all
  markdown.** `archive` + `.claude` are ~6% of files and cannot plausibly hold
  6,500 extra errors.
- Ruled out the config too: `eslint.config.js` has exactly one commit,
  `b630512` (2025-09-04), the same commit that removed the legacy `.eslintrc*`
  — so the flat-config migration predates the 743 measurement by nine months
  and is not the cause. Installed `eslint` is 9.34.0 against a declared
  `^9.32.0`; that drift is real but far too small to explain 6.5x.

**What did NOT work:**

  recently" without checking whether they contain lintable files at all —
  `ylsbrain/` is markdown, which one `git ls-files` would have shown before I
  ever raised it. **Check the denominator before proposing a shortcut.**

  exceeded 9 minutes and was killed without producing a number, and a
  `Get-ChildItem -Recurse` file count walked `node_modules` before filtering and

  tool for searching; both are instant.**
- The 6.5x growth is **still unexplained**. Code growth (~1-2% more files),
  config history and dependency drift all fail to account for it. Most likely
  the original 743 was measured on a narrower scope than `eslint .`. Recorded as
  open rather than guessed at.
