### [00:10] Diagnosed the repeating Stop-hook block; found the real cause   (branch: develop · commits: none — read-only investigation)

**Synopsis:** The Stop hook kept blocking session end across several turns
even after journal entries were written. Read `.claude/hooks/stop.js`,
`brain-lib.js`, and `post-tool-use.js` (no edits — these are vendored/sync-
managed per project CLAUDE.md Rule 11) to find the actual cause instead of
continuing to add one-line entries and hoping.

**What worked + Evidence:** Traced the mechanism precisely.
- `post-tool-use.js` logs a ledger line only for `Edit`/`Write`/`MultiEdit`
  and `git commit` Bash calls (`brain-lib.js:39-42`).
- `stop.js` blocks when any ledger line is newer than `lastCoveredTs`
  (`unconsumed()`, `brain-lib.js:51-54`), and only advances `lastCoveredTs`
  when `journalBlocks()` finds an "ok" block in the *latest* journal file
  (`stop.js:15-16,23-29`).
- `journalBlocks()` marks a block "ok" only via a strict regex:
  `/\*\*What did NOT work:\*\*\s*\S/` AND `/Evidence:\s*\S/`
  (`brain-lib.js:68`). **My own earlier entries this session used the
  heading `**What did NOT work / still open:**` — the extra text before the
  colon means the exact substring never matches, so `ok` was false, so
  `lastCoveredTs` never advanced, so every subsequent Edit/Write/commit
  (including the no-op entries and their own commits) stayed permanently
  "unconsumed" and kept re-blocking.** The no-op one-liners are expected to
  fail `ok` too (by design — real work should use the full template), which
  is why the hook's own 2-block loop-breaker (`stop.js:31-34`) exists as the
  fail-open safety net for that case.
- Evidence for the fix: this entry uses the exact required heading below: it
  should be the first block this session that actually sets `covering=true`.

**What did NOT work:** Repeating bare `no substantive task - nothing to
record` entries across three prior blocks did not stop the hook, because
those entries were never going to satisfy `ok` — they're a valid escape hatch
per `ylsbrain/CLAUDE.md`, but only in combination with the 2-block fail-open,
not by advancing `lastCoveredTs` directly. Assuming "any entry, any heading"
would satisfy the hook was the wrong model of how it works.
